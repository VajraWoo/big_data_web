# Token预算与交付约束

Token和使用额度是项目资源，不是可以忽略的对话成本。若Token使用过多，导致项目无法继续、无法按时交付，前面完成的一切都失去意义，应直接判定为项目执行失败。

## 执行规则

1. 一个任务只选择一种已经确定的方法。除非用户明确要求，不做候选算法横向跑数。
2. 不使用真实数据小样本做流程试跑。纯函数单元测试不得读取项目数据；正式数据处理只运行一次。
3. 不重复读取完整的规约、方案和技能文件。后续任务以已经形成的任务清单和当前上下文为准。
4. 默认单项任务最多包含一次必要读取、一次代码编辑、一次最小验证、一次正式运行和一次结果读取。
5. 命令日志写入本地文件。成功时只读取退出状态和最终结果；失败时只读取定位根因所需的末尾内容。
6. 不生成用户未要求的报告、总结、图表或辅助文档。
7. 不因“更加完整”主动扩大任务范围。新增依赖、模型、检查或重构必须直接服务于当前任务。
8. 同一任务首次失败时只修明确根因。第二次仍失败则暂停并说明，不继续试错消耗额度。
9. 如果发现单项任务的对话或工具开销明显超过其交付价值，立即停止，不以“已经投入很多”为理由继续消耗。

## Token优先级

Token首先用于能够形成最终系统的数据处理、代码和可验证结果。其次用于必要的错误定位。重复说明、过程复述、格式润色、大段日志和没有产物的探索性检查优先取消。

## 完成标准

任务完成以实际产物为准，不以读取了多少材料、运行了多少检查或输出了多少文字为准。任何做法只要威胁剩余额度和按时交付，即使流程形式正确，也必须停止或简化。
