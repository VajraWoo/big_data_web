# 队员环境配置说明

本文面向使用 Windows 11 的项目成员。完成配置后，可以在本机启动 Spark、MongoDB、FastAPI、Vue 和 CPU 文本分析环境。

## 一、需要安装的软件

安装以下软件：

1. Git
2. WSL 2 和 Ubuntu
3. Docker Desktop

在管理员 PowerShell 中安装 WSL：

```powershell
wsl --install -d Ubuntu
```

重启电脑，打开 Ubuntu 完成首次初始化。随后安装 Docker Desktop，并在设置中确认：

- `Use the WSL 2 based engine` 已开启；
- `Resources > WSL Integration` 中已启用 Ubuntu；
- Docker 使用 Linux containers。

项目当前按 32 GB 内存的电脑配置。可在 `%UserProfile%\.wslconfig` 中写入：

```ini
[wsl2]
memory=20GB
swap=4GB
```

保存后执行：

```powershell
wsl --shutdown
```

重新启动 Docker Desktop。内存不足 24 GB 的电脑先联系负责数据平台的成员调整 Compose 资源，不要直接运行全量清洗。

## 二、下载项目

在准备存放项目的目录中执行：

```powershell
git clone https://github.com/VajraWoo/big_data_web.git
cd big_data_web
```

以后同步代码使用：

```powershell
git pull origin main
```

检查 Docker：

```powershell
docker version
docker compose version
```

两条命令都应正常显示版本信息。

## 三、下载数据集

创建数据目录：

```powershell
New-Item -ItemType Directory -Force data\bronze\amazon_reviews_2023\appliances
```

下载评论和商品元数据：

```powershell
curl.exe -L "https://mcauleylab.ucsd.edu/public_datasets/data/amazon_2023/raw/review_categories/Appliances.jsonl.gz" -o "data\bronze\amazon_reviews_2023\appliances\Appliances.jsonl.gz"
curl.exe -L "https://mcauleylab.ucsd.edu/public_datasets/data/amazon_2023/raw/meta_categories/meta_Appliances.jsonl.gz" -o "data\bronze\amazon_reviews_2023\appliances\meta_Appliances.jsonl.gz"
```

核对文件：

```powershell
Get-Item data\bronze\amazon_reviews_2023\appliances\*.jsonl.gz | Select-Object Name,Length
Get-FileHash data\bronze\amazon_reviews_2023\appliances\Appliances.jsonl.gz -Algorithm SHA256
Get-FileHash data\bronze\amazon_reviews_2023\appliances\meta_Appliances.jsonl.gz -Algorithm SHA256
```

正确结果如下：

| 文件 | 大小 | SHA-256 |
|---|---:|---|
| `Appliances.jsonl.gz` | 270,209,794 字节 | `150F209BEFCEAA6F837ABC997065B2D251034BBBDA19BEBC4AD56DAC779730C2` |
| `meta_Appliances.jsonl.gz` | 66,406,659 字节 | `5A94CFFB9EC3BE23E42B99643FCAB5F48160B3C7A53835451C4457AADCDF9365` |

摘要不一致时重新下载对应文件。

## 四、启动 Spark 和 MongoDB

在项目根目录构建 Spark 镜像：

```powershell
docker compose -f infra/compose.yaml build spark-master
```

首次构建会下载基础镜像和 Python 依赖。构建完成后启动服务：

```powershell
docker compose -f infra/compose.yaml up -d --wait --wait-timeout 180
docker compose -f infra/compose.yaml ps
```

`ps` 应显示以下四个服务：

- `mongodb`
- `spark-master`
- `spark-worker-1`
- `spark-worker-2`

浏览器地址：

| 页面 | 地址 |
|---|---|
| Spark Master | http://localhost:8080 |
| Spark Worker 1 | http://localhost:8081 |
| Spark Worker 2 | http://localhost:8082 |

运行 Spark 环境检查：

```powershell
docker compose -f infra/compose.yaml --profile tools run --rm spark-driver
```

命令结束时应出现包含 `"status": "PASS"` 的 `ENVIRONMENT_RESULT`。

## 五、启动后端和前端

执行：

```powershell
docker compose -f infra/compose.yaml -f infra/compose.web.yaml --profile web up -d --build --wait --wait-timeout 120 backend frontend
```

打开：

| 服务 | 地址 |
|---|---|
| 前端 | http://localhost:5173 |
| 后端健康接口 | http://localhost:8000/api/v1/health |
| FastAPI 接口文档 | http://localhost:8000/docs |

健康接口正常时会返回：

```json
{"service":"ok","mongodb":"ok","active_run":null}
```

前后端依赖已经写入 Docker 镜像，队员不需要在 Windows 中单独安装 Node.js、Python 包或 MongoDB。

## 六、配置 CPU 文本分析环境

构建镜像：

```powershell
docker compose -f infra/compose.nlp.yaml --profile ml build nlp-check
```

下载 DistilBERT 和 MiniLM 模型：

```powershell
docker compose -f infra/compose.nlp.yaml --profile ml run --rm nlp-download
```

下载完成后运行环境检查：

```powershell
docker compose -f infra/compose.nlp.yaml --profile ml run --rm nlp-check
```

模型保存在 Docker volume 中，后续不需要重复下载。团队统一以 CPU 容器作为基础环境。Intel XPU 配置只用于具备相应硬件的电脑，操作见 `ml/xpu/README.md`。

## 七、运行清洗程序

先运行 10,000 条固定随机样本：

```powershell
powershell -ExecutionPolicy Bypass -File pipelines/run_silver.ps1 -Mode sample
```

样本运行成功后，可按任务安排执行全量清洗：

```powershell
powershell -ExecutionPolicy Bypass -File pipelines/run_silver.ps1 -Mode full
```

清洗结果写入 `data/silver/`。每次运行会生成独立批次，不会覆盖已有结果。全量清洗由数据平台与存储负责人统一执行，其他成员可以直接使用共享的 Silver 结果。

## 八、日常启动和停止

日常启动基础服务：

```powershell
docker compose -f infra/compose.yaml up -d --wait --wait-timeout 180
```

需要页面时再启动前后端：

```powershell
docker compose -f infra/compose.yaml -f infra/compose.web.yaml --profile web up -d --wait --wait-timeout 120 backend frontend
```

停止前后端：

```powershell
docker compose -f infra/compose.yaml -f infra/compose.web.yaml --profile web stop frontend backend
```

停止全部基础服务：

```powershell
docker compose -f infra/compose.yaml down
```

不要在 `down` 后添加 `-v`，否则 MongoDB 数据、模型缓存和环境检查结果会被删除。

## 九、常见问题

### PowerShell 找不到 docker

关闭当前 PowerShell，确认 Docker Desktop 已经启动，再打开新的 PowerShell。

### 容器启动超时

查看状态和日志：

```powershell
docker compose -f infra/compose.yaml ps
docker compose -f infra/compose.yaml logs --tail 100
```

同时确认 Docker Desktop 分配到足够内存。

### 8080、8081、8082、8000 或 5173 端口被占用

关闭占用对应端口的程序，再重新启动项目。不要自行修改 Compose 端口后提交代码。

### 模型下载失败

确认可以访问 Hugging Face，然后重新执行 `nlp-download`。已经下载成功的文件会保存在 Docker volume 中。

### Spark 作业导致电脑卡顿

停止 NLP 任务和暂时不用的前后端容器。Spark 全量清洗与模型训练不要同时运行。

## 十、配置完成的判断标准

完成以下检查即可开始项目开发：

- `docker compose ps` 中 MongoDB、Spark Master 和两个 Worker 状态正常；
- Spark Master 页面能看到两个 Worker；
- `spark-driver` 环境检查返回 `PASS`；
- 前端、健康接口和 FastAPI 文档可以打开；
- `nlp-check` 正常完成；
- 两个原始数据文件的大小和 SHA-256 与表格一致。
